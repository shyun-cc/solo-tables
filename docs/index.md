# 二十桌自部署指南

二十桌是面向微小型单店的免费开源点单收银系统。一家店准备一台云主机和一个域名，店员通过电脑或安卓平板营业，顾客用手机扫桌码点餐。

**发布进度**　目前开放的是一期部署指南。可安装的 Compose 发布包、镜像版本和收银 APK 将随产品版本提供。准备环境时可先完成下列第一步，安装及营业检查适用于发布包交付后。[查看产品版本](https://github.com/shyun-cc/solo-tables/releases)

## 1. 准备一台云主机和一个域名

1. 在阿里云、腾讯云等服务商准备有公网 IP 的 Linux 轻量服务器或 ECS，准备持久磁盘和独立的备份位置。
2. 安装 Docker Engine 和 Compose 插件。在服务器运行 `docker compose version` 确认命令可用。
3. 在域名服务商添加 A 记录，将门店域名指向云服务器公网 IPv4。配置 AAAA 时也要确保 IPv6 能到达同一入口。
4. 云安全组及主机防火墙放行 TCP 443。如需通过 HTTP 初始化或长期支持 HTTP 跳转，同时放行 TCP 80。只用 443 的门店请直接打开 HTTPS 地址。

平板、电脑和顾客手机都向云主机发起连接。门店路由器无需做端口转发。

## 2. 启动服务

取得同一版本的 Compose 文件及配套配置样例，按该版本说明设置门店域名、持久数据目录和初始凭据。在包含 Compose 文件的目录运行：

```sh
docker compose config --quiet
docker compose up -d
docker compose ps
```

访问门店域名。Web UI、顾客 H5、菜品图片和支付通知共用一个入口；容器内部访问 PostgreSQL 18 和 Silo。队列与缓存使用 PG18 扩展，安装者无需另配缓存服务器、对象存储域名或反向代理路径。

## 3. 启用正式证书

首次可通过自签名 HTTPS 进入初始化页面，或通过 HTTP 80 打开安装入口。使用自签名证书时，先向服务器管理员核对证书指纹。HTTP 初始化仅用于引导，进入加密连接后再输入管理凭据或上传私钥。

在 Web UI 的证书设置中选择自动签发并续期，或上传门店域名的证书链及配套私钥。使用自动签发时，先核对公网 DNS 及 443 连通性；使用自有证书时，记录到期日并及时替换。用未安装自签名证书的手机打开正式 HTTPS 地址，确认域名正确、证书受信任，再分发桌码。

## 4. 配置门店并检查支付

- 在店员端配置桌台和菜单，上传一张菜品图片。用手机移动网络打开顾客菜单，确认图片能加载。
- 为每张桌生成独立二维码，打印前分别扫码核对桌号。桌码中的 HTTPS 地址与支付平台使用同一公网域名。
- 分别开通门店的微信支付和支付宝商户收款能力。根据渠道要求在商户后台配置授权域名或支付应用，把各渠道签名所需材料保存在店内系统的管理配置中。将系统给出的对应支付通知地址用于渠道配置或下单请求。
- 分别验证两条支付链路。顾客扫码后确认桌号、下单并完成支付；店员从电脑和平板查看同一订单，核对桌号、实收金额及渠道流水。支付后立即关闭 H5，也应能在店员端确认结果。

## 5. 连接收银平板

安装对应版本的 APK。首次启动在「连接门店」输入域名并连接，成功后登录。下次启动自动访问上一次连接成功的服务器。网络故障时，应用回到地址页并保留原值，可重试或修改；登录过期时在原门店重新登录。

换店或更换域名时，从 App 设置修改服务器地址，连接成功后再登录新地址。将蓝牙打印机和扫码枪与红米平板配对，实际打印一张小票，再用扫码枪完成一次业务输入。电脑浏览器可完成同样的店员业务操作，蓝牙设备由平板使用。

## 6. 备份、恢复及故障定位

- 同时备份 PG18 业务数据、Silo 图片、部署配置及证书所需的持久数据，密钥单独加密保管。备份副本放到云主机之外。更换版本前记录当前版本并完成备份。
- 换机演练时，先在独立主机恢复匹配版本。核对历史订单、支付流水及菜单图片，再验证平板连接。完成检查后再切换 DNS。
- 网页打不开，先核对域名、云安全组和 `docker compose ps`；只有图片加载失败，检查 Silo 服务、持久卷及应用访问 Silo 的凭据。
- 顾客已付款但店员端仍待确认，保留订单号和渠道交易号，查询渠道交易结果并检查通知入口及签名配置，避免让顾客重复付款。对外反馈问题前先移除日志中的凭据和顾客信息。
